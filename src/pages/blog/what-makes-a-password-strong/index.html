What actually makes a password strong

Strength is not about odd symbols. It comes down to length and randomness. Here is what matters, and how to get it without having to invent anything yourself.

Length beats complexity, and the gap is enormous

A long password built from ordinary characters is harder to crack than a short one crammed with symbols, because every extra character multiplies the number of guesses an attacker has to make rather than adding to it.

Some arithmetic to show the scale. Using upper case, lower case, digits, and the symbols on a standard keyboard gives a pool of 87 characters per position. Adding four characters to a password multiplies the number of possible values by 87 to the fourth power, which is about 57 million. Four characters. Not 57 million more combinations, 57 million times as many.

Compare the two ends of that. Eight lower case letters give about 210 billion possibilities, which sounds enormous and is not: dedicated hardware works through that range quickly. Sixteen characters from the full pool give a number with 31 digits in it. The second is about 52 quintillion times larger than the first, and the only thing that really changed was length.

Now compare that with the classic complexity trick. Swapping a 3 for an E, or an @ for an a, moves you nowhere, because cracking tools apply those substitutions as standard rules. A dictionary word with predictable substitutions is a dictionary word.

Randomness is the other half

A password is only as good as it is unpredictable. Anything chosen by hand falls into a pattern that cracking tools already expect: a name, a date, a keyboard run, a word with the first letter capitalised and a 1 on the end. The search space above assumes every position is equally likely. Pick by hand and you collapse it, whatever the password looks like.

This is where "must contain one upper case, one number, and one symbol" rules quietly backfire. Faced with them, most people produce a capital at the front, a digit at the end, and an exclamation mark after that. The rule adds a symbol and removes the unpredictability that actually mattered, which is why P@ssw0rd! satisfies almost every corporate policy and is among the first things any attacker tries.

The thing that matters more than either

A perfect password used in two places is weaker than a mediocre one used once. When a site is breached, the stolen pairs of address and password get replayed against banks, email providers, and shopping sites automatically. The attacker never has to crack anything, because you already gave them a working password: they are just trying it on a different door.

So the ranking is: never reuse, then make it long, then make it random. Most people work that list backwards.

You are not meant to remember it

Random passwords feel impractical because people try to memorise them, which is the wrong job for a person. Save each one in your browser or a password manager and let the machine hold it. The single password worth committing to memory is the one that unlocks the manager, and that one can be a long passphrase of unrelated words, since length is doing the work.

Making one

The password generator has a length slider up to 64 and toggles for the four character types. A few notes on using it:

  • Sixteen is a sensible floor. Go higher wherever the site allows it, since the cost to you is zero when a manager is doing the typing.
  • Turning off symbols weakens things far less than shortening the password does, so if a site rejects them, add a few characters instead of arguing with the form.
  • The "No look-alikes" toggle drops characters like 0 and O, 1 and l. Worth it for a password you will read aloud or copy off a screen, unnecessary otherwise.

It draws from crypto.getRandomValues, the browser's cryptographic random source, rather than Math.random, and it discards values that would land unevenly across the character set instead of taking a remainder. That second part matters: a plain remainder makes the first few characters of the set slightly more likely, and slightly predictable is exactly what you were trying to avoid.

The password is generated in your browser and never sent anywhere.
