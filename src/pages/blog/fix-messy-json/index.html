How to fix messy JSON and read the error

When JSON will not parse, the message you get back can be blunt. Here is how to make a file readable, and how to find the character that is actually breaking it.

Format first, read second

Minified JSON on a single line is hard to scan for a missing bracket. Formatting it adds indentation and line breaks so the structure becomes visible, which on its own often shows where a level was opened and never closed. Paste your JSON into the JSON formatter and press Format. Two spaces, four spaces, or tabs, depending on what the file around it uses.

The error points at where parsing stopped

This is the part that wastes the most time. A parser reads left to right and complains at the first point where what it sees cannot possibly continue. That is often a line or two after the actual mistake.

A missing comma is the clearest case. Leave one out after a value and the parser happily reads the value, then finds a quoted key where it expected a comma or a closing brace, and reports the error there. You stare at the reported line, which is perfectly correct, while the real problem sits at the end of the line above it.

So treat the position as a starting point and read backwards from it. The formatter converts the raw character offset into a line and column, which is enough to land you in the right neighbourhood.

What usually causes it

Most failures come from a short list:

  • A trailing comma after the last item in an object or array. Valid in JavaScript, not in JSON.
  • Single quotes where JSON requires double quotes, or a key with no quotes at all.
  • Comments. JSON has none, and // or /* */ in a config file will stop a strict parser even though the editor highlighted them nicely.
  • A bracket or brace opened and never closed, which usually gets reported at the very end of the file.
  • Values that only exist in JavaScript: undefined, NaN, Infinity, and numbers written as .5 or 01.

The one that comes from copying and pasting

If the JSON came out of a chat message, an email, or a word processor, suspect the quotes before anything else. Those tools rewrite straight quotes as curly ones, and a curly quote is not a string delimiter, it is just a character the parser did not expect. The two look nearly identical in most fonts, which is what makes this one maddening. The same applies to a non-breaking space pasted in place of a normal one.

The problem that never raises an error

Duplicate keys are legal enough that most parsers accept them without complaint, and simply keep the last one. So a config with a setting listed twice parses cleanly and quietly ignores the value you meant to use. If a setting seems to have no effect, search the file for the key before assuming the software is at fault. Nothing will flag it for you.

Minify when you are done

Once the JSON is valid you may want it small again for a config field, a request body, or an environment variable. Minify strips the whitespace back out and leaves the smallest valid version of the same data.

Format, validate, or minify with the JSON formatter. Nothing is uploaded, so it is safe for config and data you cannot share.
