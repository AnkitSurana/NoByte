How to turn JSON into TypeScript types

When you get JSON back from an API, writing the TypeScript types by hand is tedious and easy to get wrong. A sample of the JSON already contains almost everything the types need. Here is how that inference works, and where it saves time.

Why a sample is enough

A response like { "id": 1, "name": "Ada", "tags": ["a", "b"] } tells you the shape directly. id is a number, name is a string, tags is an array of strings. The JSON to TypeScript tool reads that structure and writes the matching interface, so you paste the JSON and copy the types out.

The value of doing it from a real sample is that it matches what the server actually sends, rather than what a stale document says it sends.

The parts it works out for you

  • Nested objects become their own named interfaces, so a profile object turns into a Profile interface referenced from the parent.
  • Arrays get an element type. An array of objects is merged into one interface rather than repeated for every item.
  • Optional fields are marked with a ?. When the tool sees several objects in an array and a key is missing from some of them, it treats that key as optional, which is usually what a real API means.
  • Unions appear when a field holds more than one type across the sample, for example string | null.

Where it helps, and where to check the result

It is quickest for the boring middle of the work: turning a fresh API response into a starting set of interfaces you can refine. It saves the typing and catches the obvious shape.

A sample cannot know two things, so glance over the output for these. A field that happens to be null in your sample could be a string in another response, so widen the type where you know more than the sample does. And a number that is really an enum, like a status of 1, comes out as number, which you may want to narrow by hand.

Try it

Open the JSON to TypeScript tool, paste a response, and the interfaces appear next to it. Load the example first if you want to see how nested objects and optional fields come out. The conversion runs in your browser, and the source is on GitHub.
