How to compress an image without it going blurry

Compression trades file size against detail, but the biggest saving is usually somewhere else entirely. Here is how to make an image smaller while keeping it looking right.

Why smaller tends to mean softer

JPG and WebP save space by discarding the detail your eye is least likely to miss. Push the quality down far enough and the losses start to show as soft edges, and as blocky patches in areas that should be flat colour: a clear sky, a plain wall. The trick is finding the point just before that begins.

Check the dimensions before you touch the quality

This is the step people skip. A photo straight off a phone can be 4,000 pixels wide. If it is going into a page that displays it at 800, three quarters of those pixels are being thrown away by the browser after being downloaded in full. No quality setting fixes that, because the file is large for a reason the slider cannot address.

Halving an image's width and height quarters its pixel count, and the file usually falls by something close to that, with no visible softening at all if you were never seeing those pixels. Compare that with dropping quality far enough to save the same space, which you would see immediately. So: resize to the size it will actually be shown at with the image resizer, then compress what is left.

The compressor deliberately keeps the original dimensions, so the two steps stay separate and you can see what each one cost you.

Using the slider

Open the image compressor and drop an image in. It starts at quality 70. Move the slider and watch the file size change next to the preview.

For most photographs the useful band is somewhere between 60 and 80. Below about 50 the artefacts become noticeable on flat areas and around hard edges. Above about 90 the file grows quickly while the improvement is difficult to see. Judge it on the preview at full size, not on a thumbnail, since a thumbnail hides exactly the problems you are looking for.

Compressing twice makes it worse

Quality is not a property of the file that you can raise and lower freely. Every save at a lossy quality discards detail permanently, and re-encoding an already-compressed JPG discards more on top, even at a high setting. Do it repeatedly and the artefacts accumulate.

The habit that avoids this: keep the original, and compress from it each time. If you have to try three quality settings, run all three from the source file rather than compressing the compressed one.

Which format, and one trap

JPG suits photographs and is accepted everywhere. WebP usually produces a smaller file at the same visible quality and handles both photographs and flat graphics, so it is worth trying wherever the destination accepts it.

The trap is transparency. JPG cannot store it, so a transparent PNG saved as JPG comes out with the see-through areas filled in white, which is rarely what anyone wanted from a logo. Choose WebP if the image has transparency you need to keep.

For screenshots and anything with sharp text, lossy compression is the wrong tool at any quality: text edges are the first thing it damages. Keep those as PNG, or convert with the image format converter.
